This folder contains the static data used by the application.

Election-specific source files:
- `btw2021/first_votes.json` and `btw2025/first_votes.json`
  - Canonical, constituency-aware first-vote `VoteEntry` records produced by the notebook workflows.
- `btw2021/second_votes.json` and `btw2025/second_votes.json`
  - Canonical, constituency-aware second-vote `VoteEntry` records produced by the notebook workflows.

The JSON files remain the human-readable prepared-data artifacts and are not modified by the runtime export. Before `npm run dev` and `npm run build`, `scripts/export-vote-binary.mjs` derives these ignored runtime files in each election directory:

- `vote_data.json`
  - Binary schema metadata, party dictionaries, constituency-to-state mapping, record counts, file sizes, and SHA-256 checksums.
- `first_votes.bin` and `second_votes.bin`
  - Fixed-width binary vote records loaded by the application instead of the large source JSON files.

The binary record layout is versioned. Version 1 uses a 16-byte file header followed by 13-byte records containing a `uint16` constituency id, `uint16` party id, one packed demographic/method byte, and one little-endian `float64` vote value. State names and repeated dimension strings are stored once in `vote_data.json` instead of once per vote record.

`npm run data:binary` can be used to regenerate the runtime files explicitly. Production builds remove the source `first_votes.json` and `second_votes.json` copies from `dist/` after Vite has copied `public/`, so GitHub Pages only serves the compact runtime vote data.

Shared and supporting files:
- `partyData.json`
  - Party names, abbreviations, colours, and parliamentary positions used across the supported elections.
- `germany_states_map.geo.json`
  - GeoJSON geometry for the German federal states.
- `state_seat_contingents_2021.json` and `state_seat_contingents_2025.json`
  - Election-year-specific distributions of the 598 initial seats among the federal states for simulations with the pre-2023 electoral-law model.

The canonical vote JSON files are generated by the notebook workflows under `scripts/notebooks/btw2021/` and `scripts/notebooks/btw2025/`. Their shared record model and preparation methodology are documented in `scripts/README.md`.

`src/data/loaders.ts` selects the matching binary vote files, metadata, and state-seat-contingent fixture for the election chosen in the application. The decoder reconstructs the existing `VoteEntry[]` contract so the electoral calculations remain unchanged by this transport-format migration.
